# Agentic-Research

> **Evidence-grounded autonomous research infrastructure for scientific discovery, from literature intelligence and gap discovery to reproducible experimentation, rigorous evaluation, autonomous research control, and publication packaging.**

[![CI](https://github.com/ZHX4/Agentic-Research/actions/workflows/ci.yml/badge.svg)](https://github.com/ZHX4/Agentic-Research/actions/workflows/ci.yml)

## Overview

Agentic-Research is a modular, end-to-end AI research platform designed to support the complete scientific workflow. It is built for technically sophisticated users who want more than literature summarization or one-shot idea generation: the system turns scientific knowledge into auditable research opportunities, challenges those opportunities against prior work, develops falsifiable hypotheses, executes reproducible experiments, evaluates the results, manages bounded autonomous research cycles, and packages validated outputs for publication.

The platform is organized around one core principle:

> **AI-assisted scientific discovery should be evidence-driven, reproducible, traceable, and scientifically accountable.**

The project is currently focused on AI/ML research, with early emphasis on reasoning and LLM systems, retrieval and RAG, memory and long-context methods, efficiency and scaling, evaluation methodology, tool use, and agentic systems.

---

## Why Agentic-Research?

Scientific literature is now too large and heterogeneous to navigate reliably with simple keyword search and summarization alone. Important ideas can be distributed across papers, sections, tables, citations, and supplementary material; equivalent concepts can be described with different terminology; and plausible “novel” ideas generated by an LLM may already exist in another form.

Agentic-Research treats this as a **scientific infrastructure problem**.

Its goals are to:

1. Build structured scientific intelligence instead of relying only on raw text.
2. Represent relationships among papers, methods, datasets, tasks, claims, evidence, and limitations.
3. Discover research opportunities using complementary signals.
4. Attack candidate gaps with adversarial novelty verification before treating them as promising.
5. Generate diverse hypotheses with explicit falsification conditions.
6. Execute experiments in bounded and reproducible environments.
7. Evaluate results with benchmark, baseline, ablation, temporal, and human-evaluation safeguards.
8. Run bounded autonomous research loops with durable state and reviewer gates.
9. Preserve provenance and release metadata so validated work can be packaged for publication.

The goal is not to replace scientists. It is to provide a rigorous AI collaborator that accelerates the parts of research that can be systematized while keeping human scientific judgment in the loop.

## End-to-End Research Pipeline

```text
Scientific Literature
        ↓
Literature Intelligence
        ↓
Scientific Document Understanding
        ↓
Persistent Scientific World Model
        ↓
Research Gap Discovery
        ↓
Adversarial Novelty Verification
        ↓
Hypothesis Reasoning
        ↓
Reproducible Scientific Execution
        ↓
Evaluation & Benchmarking
        ↓
Bounded Autonomous Research Control
        ↓
Publication & Reproducibility Packaging
```

Each phase produces structured artifacts with explicit schemas and provenance. Downstream phases consume those artifacts rather than depending on hidden conversational state.

A key methodological rule is deliberately enforced throughout the system:

> **Failure to find prior work within a bounded search process is not proof of global novelty.**

The project therefore uses states such as `candidate`, `weakened`, `survived`, `disproved`, and `inconclusive` instead of collapsing uncertainty into unjustified certainty.

## Architecture by Phase

### Phase 0 — Foundation

Establishes the repository structure, engineering conventions, schemas, configuration, development tooling, and quality baseline.

### Phase 1 — Literature Intelligence

Provides literature acquisition, source adapters, transport, identity normalization, deduplication, and full-text acquisition infrastructure.

### Phase 2 — Scientific Document Intelligence

Transforms scientific documents into structured representations including sections, chunks, tables, figures, claims, evidence, and citations.

### Phase 3 — Scientific World Model

Creates persistent relationships among papers and scientific entities so downstream reasoning can operate on a structured knowledge representation rather than isolated documents.

### Phase 4 — Research Gap Discovery

Searches for research opportunities such as missing combinations, recurring limitations, contradictions, underexplored conditions, cross-domain connections, and graph negative-space. Its output is a set of **candidate gaps**, not proven novelty.

### Phase 5 — Adversarial Novelty Verification

Actively challenges candidate gaps through expanded retrieval, prior-work comparison, temporal constraints, counterevidence, and bounded full-text verification. Evidence from external papers can be reprocessed through the scientific intelligence pipeline so exact method/dataset/task relationships are not inferred from metadata alone.

### Phase 6 — Hypothesis Reasoning

Transforms verified opportunities into diverse and falsifiable hypotheses using multiple generation strategies, structured reflection, confounder analysis, deduplication, clustering, tournament ranking, Pareto selection, and bounded evolution.

Every hypothesis carries an explicit falsification condition.

### Phase 7 — Scientific Execution

Turns selected hypotheses into experiment specifications and executes them inside controlled environments with code/data integrity checks, dataset manifests, resource limits, multi-seed execution, explicit metric validation, artifact hashes, and falsification decisions.

### Phase 8 — Evaluation & Benchmarking

Evaluates system behavior across retrieval, extraction, gap/novelty classification, temporal leakage, human assessment, baseline comparison, ablations, and compute/cost accounting. It also enforces prediction coverage and benchmark split-contamination checks.

### Phase 9 — Autonomous Research Control

Provides the closed-loop control plane for research runs with durable SQLite state, checkpoints, integrity verification, bounded retries and iterations, no-progress detection, stage-specific reviewers, critical-stop policies, provenance harvesting, and resumable execution.

Production runs use explicit adapters for the canonical Phase 4–8 implementations; deterministic identity adapters are restricted to explicit smoke-test mode.

### Phase 10 — Publication & Release Packaging

Produces evidence-gated publication artifacts including system manuscripts, benchmark papers, discovery case studies, reproducibility packages, model/provider disclosures, licensing audits, and a final publication-readiness decision.

Phase 10 never invents missing results or upgrades an incomplete scientific record into a ready release.

## Core Components

### Literature Layer

Source adapters, transport, identity normalization, deduplication, and full-text retrieval.

### Intelligence Layer

Structured extraction of sections, chunks, figures, tables, claims, evidence, and citations.

### Retrieval & World Model

Lexical/dense/hybrid retrieval, reranking, persistent scientific graph structures, and vector-oriented representations.

### Gap Discovery Engine

Multiple complementary detectors for structurally different kinds of research opportunities.

### Novelty Verification Engine

Adversarial prior-work search, temporal safeguards, evidence comparison, deep verification, and provenance tracking.

### Hypothesis Engine

Generation, reflection, diversity analysis, clustering, evolution, tournament selection, and Pareto ranking.

### Experiment Engine

Sandboxed execution, dataset/code integrity validation, multi-seed runs, metrics ingestion, reproducibility metadata, and experiment trees.

### Evaluation Engine

Scientific metrics, human-rater agreement, temporal leakage analysis, baseline comparisons, ablations, cost summaries, and deterministic composite reports.

### Autonomous Control Plane

Checkpointed state machines, reviewer panels, durable state storage, artifact hashing, resume semantics, and bounded autonomous research cycles.

### Publication Engine

Manuscript builders, reproducibility manifests, disclosure handling, licensing review, release-time artifact verification, and publication-readiness gating.

## Key Design Principles

### Evidence before conclusions

Important decisions should be backed by explicit evidence and provenance rather than unsupported model output.

### Reproducibility by construction

Code, datasets, configuration, environment information, seeds, metrics, artifacts, and hashes are treated as research objects.

### Fail closed on missing evidence

Missing or invalid evidence should produce `blocked` or `inconclusive`, not an optimistic result.

### Bounded autonomy

Autonomous behavior is limited by retry budgets, iteration limits, resource controls, checkpoints, and reviewer policies.

### Explicit stage boundaries

Each phase owns a specific scientific or orchestration responsibility, making failures easier to diagnose and components easier to replace.

### Deterministic artifacts

Stable identifiers, reproducibility manifests, content-addressed reports, and explicit provenance make runs easier to compare and audit.

### Human scientific oversight

The system augments researchers rather than replacing domain expertise, scientific interpretation, or publication review.

## Installation

### Requirements

- Python 3.11+
- Git
- Docker for Phase 7 experiment execution
- A local filesystem for persisted artifacts and autonomous run state

### Install from source

```bash
git clone https://github.com/ZHX4/Agentic-Research.git
cd Agentic-Research

python -m venv .venv

# Linux / macOS
source .venv/bin/activate

# Windows PowerShell
# .venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
pip install -e ".[dev]"
```

Optional embedding support:

```bash
pip install -e ".[embeddings]"
```

All optional project dependencies:

```bash
pip install -e ".[all]"
```

### Environment configuration

Copy `.env.example` to a local `.env` when provider credentials or deployment-specific settings are required. Never commit real secrets.

The default environment template is deliberately conservative and includes request timeouts and source-specific rate limits.

## Typical Workflows

### 1. Candidate gap → novelty verification

Start from a Phase 4 gap artifact and run the Phase 5 verifier:

```bash
agentic-research-verify --help
```

Inspect the verification report for direct prior work, near matches, counterevidence, temporal coverage, and deep-verification outcomes before advancing.

### 2. Verified gap → hypothesis run

Feed the Phase 5 report to the Phase 6 hypothesis engine:

```bash
agentic-research-hypotheses --help
```

The result includes hypotheses, reflections, clustering information, selected IDs, Pareto-frontier IDs, and lineage.

### 3. Hypothesis → reproducible experiment

Plan and execute experiments through Phase 7:

```bash
agentic-research-execution --help
```

The execution layer treats missing or malformed required metrics as a failed scientific run rather than a successful experiment.

### 4. Results → evaluation report

Build benchmark-specific artifacts and then a composite evaluation report:

```bash
agentic-research-evaluation --help
```

### 5. Evaluation → autonomous research cycle

Production autonomous runs are driven by canonical Phase 4–8 adapters:

```bash
agentic-research-autonomous --help
```

Autonomous state is persisted so a run can be resumed without restarting completed stages.

### 6. Validated results → publication package

Use Phase 10 to create a release package:

```bash
agentic-research-publication --help
```

The publication bundle remains `blocked` until evidence, disclosures, reproducibility artifacts, and licensing checks satisfy the release gate.

## Configuration and Customization

Configuration is centralized in [`configs/default.yaml`](configs/default.yaml), while environment-specific values belong in `.env`.

Important customization points include:

- literature providers and transport settings;
- retrieval and reranking behavior;
- temporal cutoffs and novelty search budgets;
- full-text verification limits;
- hypothesis generation and evolution budgets;
- experiment CPU, memory, PID, timeout, and seed limits;
- evaluation thresholds, split rules, and bootstrap settings;
- autonomous retry/iteration limits and review policies;
- publication artifact and licensing metadata.

The architecture is provider-independent. Model, search, retrieval, and stage implementations can be replaced as long as they respect the canonical contracts and preserve provenance.

## Reproducibility and Scientific Integrity

Agentic-Research records or can derive provenance for major research artifacts, including:

- paper identities and source metadata;
- evidence references;
- verification outcomes;
- hypothesis lineage;
- dataset manifests;
- code and data hashes;
- execution environments;
- seeds and experiment results;
- evaluation reports;
- publication manifests.

Phase 7 uses restricted execution defaults, while Phase 8 validates benchmark splits and prediction coverage. Phase 9 persists state and checkpoints. Phase 10 re-hashes release artifacts and audits licensing before a bundle can become ready.

These safeguards are intended to reduce false claims, improve reproducibility, and make failures inspectable.

## Contribution Guidelines

Read [`CONTRIBUTING.md`](CONTRIBUTING.md) before contributing.

In general:

1. Create a focused branch from `main`.
2. Follow the phase contracts relevant to your change.
3. Add regression tests for behavioral changes.

5. Run the local quality gate before submitting a pull request.
6. Explain scientific-integrity implications for changes affecting verification, hypotheses, experiments, evaluation, autonomy, or publication.

Do not commit credentials, private datasets, or generated artifacts containing secrets.
